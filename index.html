11.1.1 元素类型及转换

先认清盒子，再谈布局。

HTML 标签先被浏览器解释成一种 display。改 display，只改变“怎么排队”，不改变标签本身的语义。

display 就是浏览器给标签安排的“排队方式”：块级像抽屉上下叠，行内像文字横向排队。

01 / BLOCK

块级元素

独占一行，默认宽度撑满父容器。width、height 和四向 margin 都有效。

像一个占满整行的抽屉，后面的盒子只能放到下一行。

divph1li
02 / INLINE

行内元素

像文字一样从左往右排队。尺寸由内容决定，直接写 width / height 通常无效。

像句子里的几个词，跟着普通文字一起从左往右站队。

spanastrongem
03 / INLINE-BLOCK

行内块元素

既能在同一行排队，又能统一设置宽高。常用于导航、标签和按钮。

像尺寸统一的小卡片，可以并排摆放，也能规定每张卡片的大小。

11.1.2 Overflow 属性

装不下时，内容该去哪里？

overflow 只在父盒子有尺寸约束时才有明显作用：露出来、裁掉、始终滚动，还是按需滚动。

把盒子想成收纳箱：东西装不下时，可以露在外面、直接剪掉，或者加一根滚动条。

省略号生成器

单行靠“三件套”，多行靠 line-clamp。拖动控件看文字如何被收住。

只留下规定行数，最后补一个“…”提醒读者后面还有内容。

03

11.1.3 元素的浮动

盒子漂到一边，文字自动绕开。

float 让元素贴向左边或右边。真正需要警惕的是：浮动子元素不再参与父容器的高度计算。

像把一张卡片推到桌边；后面的文字看到它，就会自然地绕开，不再从它身上压过去。

11.1.4 清除浮动

把漂起来的盒子，重新装回父容器。

认识四种方法即可，不必全背。现代项目优先 clearfix 或 display: flow-root。

像在容器底部塞一个看不见的挡板，把漂起来的卡片重新兜住，让父容器知道自己有多高。

方法写法代价 / 副作用适用判断
额外标签末尾空 div + clear: both增加无意义 DOM，结构变脏★★ 理解原理、考试
overflow父级 overflow: hidden/auto可能裁剪菜单、阴影，可能导致 sticky 异常★★ 父级本来就要裁切
clearfix父级伪元素 + clear: both几乎无，兼容性稳定★★★★ 维护老项目首选
flow-root父级 display: flow-rootIE 不支持★★★★ 现代项目首选
clearfix.css · 可直接复用
/* 加在浮动元素的父级 */
.clearfix::after {
  content: "";
  display: block;
  clear: both;
}
DECISION / 2026

新项目：flow-root
老项目：clearfix

两者都不会裁剪内容。不要给父元素写死固定高度，那只是在掩盖内容变化后的溢出风险。

clear: both 作用在“要被移动的那个元素”上，而不是写在浮动元素自己身上。

一个新闻列表，收住四个知识点。

封面左浮动，文字自然环绕；标题单行省略，简介两行截断；父级 clearfix 重新收住高度。

06

复习 / 自测 / 总结

把踩过的坑，变成上机检查表。

先完成六项检查，再点开三道快问快答。能用自己的话讲清，才算真正掌握。

检查表就是一张排错地图：先看盒子类型，再看内容有没有溢出，最后检查父容器有没有被浮动“骗”到高度为 0。

Q1 / INLINEspan 设了 width: 200px，为什么没反应？点开答案 +
行内元素的宽高无效，尺寸由内容决定。要设置宽高，改成 inline-block 或 block。
Q2 / OVERFLOWscroll 和 auto 的区别是什么？点开答案 +
scroll 始终显示滚动条；auto 只在内容真的溢出时出现滚动条。
Q3 / CLEARclear: both 能“删除”浮动吗？点开答案 +
不能。它只让当前块级元素移动到浮动元素下方；浮动本身仍存在，原来的位置也不会恢复。
01 / DISPLAY

元素类型

决定是否独占一行，以及宽高能否生效。

02 / OVERFLOW

内容溢出

决定多出来的内容是露出、裁掉还是滚动。

03 / FLOAT

元素浮动

让盒子贴边并排，文字自动绕排。

04 / CLEAR

清除浮动

让父容器重新获得高度，收住整片浮动。

如果只记住一句话：先判断元素类型，再谈布局。
